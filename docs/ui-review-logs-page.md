# Manabi Voice UI 修正依頼: logs ページ

このファイルは Codex CLI に読ませるための UI 修正指示です。

## 前提

- このアプリは要約アプリではありません。
- ユーザーが話した/書いた学びを日誌として残し、理解状態を点検するアプリです。
- UI は「ログ管理ツール」ではなく、「学びの日誌を読み返す」体験に寄せたいです。
- 外部 API 接続、DB 構造、認証、課金サービスなどは触らないでください。
- 既存の `/logs/[id]`、`/days/[date]`、`getRecentLogs`、`getLogDates`、`LogList` を活かしてください。
- TypeScript で実装してください。
- Next.js のバージョンが通常と異なる可能性があるため、必要に応じて `node_modules/next/dist/docs/` の関連ガイドを確認してから実装してください。

## 今回の主目的

`/logs` を「最近のログ一覧」ではなく、**過去の日誌を探して読み返すページ** にしてください。

現状は `/logs` の上部に `最近の日誌` があり、その下に `日付から読む` があります。
これだと「新着順の管理一覧」に見えます。

修正後は、ユーザーがまず **日付から過去の日誌を探せる** ようにしてください。

## 必須修正 1: `/logs` の情報設計を変更

対象:

- `src/app/logs/page.tsx`

現在:

1. ヒーロー
2. 最近の日誌
3. 日付から読む

希望:

1. ヒーロー
2. 日付から読む
3. 最近の日誌

または、余裕があればデスクトップでは以下の 2 カラム構成にしてください。

- 左またはメイン: `日付から読む`
- 右または補助: `最近の日誌`

ただし、モバイルでは必ず `日付から読む` が先に来るようにしてください。

### UI 意図

`/logs` は一覧を読むページではなく、読み返す入口です。
ファーストビュー内に `日付から読む` が見えることを優先してください。

### `日付から読む` の見え方

現在の月ごとの日付リンクは方向性として良いです。
ただし、もう少し「検索・索引」らしく見えるとよいです。

例:

- セクション見出し: `日付から読む`
- 補足文: `その日に残した日誌だけをまとめて開けます。`
- 月見出し: `2026-06`
- 日付チップ: `6/26  4件` など、短くしてもよい
- URL は既存通り `/days/[date]`

日付チップはボタン/チップのように見えるとよいです。
カード全体を重くしすぎないでください。

## 必須修正 3: `/logs` では compact 表示を使う

対象:

- `src/app/logs/page.tsx`
- `src/components/LogList.tsx`

`/logs` の `最近の日誌` では以下のように使ってください。

```tsx
<LogList logs={recentLogs} variant="compact" />
```

### compact の目的

`/logs` ではカードの文字量が多すぎます。
最近の日誌は「読む本文」ではなく、「目的の日誌を見つけるための索引」です。

### compact 表示の仕様

compact では、できれば以下にしてください。

表示する:

- 日付
- タイトル
- 元の学び `sourceText` を 1〜2 行
- 短い状態ラベル

表示しない、またはかなり短くする:

- `learningNote.noteBody` の長いプレビュー
- `点検メモ 4件` のような件数強調

推奨:

- `sourceText`: `line-clamp-2`
- `learningNote.noteBody`: 非表示でよい。出すなら `line-clamp-1` で薄く。
- カード余白は default より少し小さくしてよい。
- バッジは横幅いっぱいにならないようにする。
- モバイルでバッジが長くなりすぎないようにする。

default 表示はホームなどで既存に近くて OK です。
ただし、既存の default も明らかに読みづらくなる変更は避けてください。

## 必須修正 4: バッジ文言を柔らかくする

対象:

- `src/components/LogList.tsx`

現状:

- `確認質問 / 点検メモ 4件`
- `発展・完了 / 点検メモ 4件`

これはまだ少し管理ツールっぽいです。

できれば、compact では短く柔らかい表現にしてください。

例:

- `問いあり`
- `復習あり`
- `補足あり`
- `よく理解`
- `確認中`

assessmentStatus / interventionType に応じて自然に出してください。
件数は compact では不要、または title/aria-label 的な補足に留めてください。

default では件数を残してもよいですが、文言は硬くしすぎないでください。
`点検メモ 4件` は許容ですが、compact では避けたいです。

## 余裕があれば: `/logs` 上部を 2 カラムにする

デスクトップ:

- ヒーロー直下に、`日付から読む` と `最近の日誌` を並べる。
- `日付から読む` を広め、`最近の日誌` を補助的にする。
- ただし、最近の日誌が長すぎて右カラムに詰まるなら無理に 2 カラムにしない。

モバイル:

- 1 カラム。
- `日付から読む` が先。
- `最近の日誌` が後。

実装の簡単さを優先するなら、まず単純に順序を入れ替えて compact 化してください。
2 カラムは無理にやらなくていいです。


## 画面ごとの目標

### `/`

目的:

- 今日の学び日誌の入口。
- 今日書く、今日読む、過去を読み返す導線が見える。

合格ライン:

- 管理ツールではなく、今日の日誌ページに見える。
- `過去の日誌を読み返す` への導線が自然。

### `/logs`

目的:

- 過去の日誌を探して読み返す棚。
- 新着一覧ではなく、日付から探す体験を優先。

合格ライン:

- ファーストビュー付近で `日付から読む` が見える。
- 最近の日誌はコンパクト。
- 文字量が多く見えない。
- モバイルでも日付チップやカードが窮屈でない。

### `/record`

今回必須ではありません。
ただし既に `学び日誌を書く`、`点検して日誌に残す` になっているなら、その方向は良いです。

### `/logs/[id]`

今回必須ではありません。
現状の `理解ノート` 主役、点検詳細折りたたみは良い方向です。

## 実装上の注意

- DB schema は変更しない。
- API route は必要なければ触らない。
- 外部 API 接続は追加しない。
- Tailwind の既存スタイルに合わせる。
- 大きなデザインシステム追加や UI ライブラリ追加は不要。
- カードの角丸を大きくしすぎない。
- 余白と文字量の整理を優先する。
- モバイル 390px 幅程度で確認する。
- テキストやバッジが横にはみ出さないこと。
